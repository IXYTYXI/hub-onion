## 新增需求

### 需求：存储服务接口
系统应定义文件操作的存储服务接口，支持流式处理。

#### 场景：流式上传操作
- **当** 上传文件时
- **则** 存储服务应接受键、io.Reader（流式数据）和内容类型参数

#### 场景：流式下载操作
- **当** 下载文件时
- **则** 存储服务应返回给定键的 io.ReadCloser（流式数据）

#### 场景：删除操作
- **当** 删除文件时
- **则** 存储服务应删除给定键的文件

### 需求：CDN 实现
系统应使用阿里云 OSS（S3 兼容）实现存储服务接口。

#### 场景：阿里云 OSS 配置
- **当** 初始化 CDN 存储时
- **则** 系统应从配置加载阿里云 OSS 凭据（AccessKeyID、AccessKeySecret）、端点和 Bucket 名称

#### 场景：S3 兼容 API 认证
- **当** 发出 OSS 请求时
- **则** 系统应使用 AWS SDK v2 通过 S3 兼容协议进行认证

#### 场景：虚拟主机风格访问
- **当** 配置 OSS 客户端时
- **则** 系统应使用虚拟主机风格（UsePathStyle = false），URL 格式为 https://{bucket}.{endpoint}/{key}

### 需求：存储键格式
系统应使用一致的键格式组织 CDN 中的文件。

#### 场景：技能文件键结构
- **当** 存储技能文件时
- **则** 系统应使用键格式：skills/{skill_id}/{version_id}/{file_path}

#### 场景：键的唯一性
- **当** 生成存储键时
- **则** 系统应确保每个版本内的每个文件键是唯一的

### 需求：流式上传处理
系统应使用流式处理上传文件以最小化内存使用。

#### 场景：边读边上传
- **当** 处理文件上传时
- **则** 系统应使用 io.Reader 流式读取文件并直接传输到 OSS，无需缓冲整个文件到内存

#### 场景：同时计算哈希
- **当** 流式上传文件时
- **则** 系统应使用 io.TeeReader 同时计算 SHA-256 哈希，避免二次读取

#### 场景：内存效率
- **当** 上传 50MB 文件时
- **则** 系统应仅使用约 32KB 缓冲区内存，而非缓冲整个 50MB

### 需求：并发上传优化
系统应支持并发上传多个文件以提高性能。

#### 场景：有限并发上传
- **当** 一个 skill 包含多个文件时
- **则** 系统应并发上传文件，并发数限制为 5

#### 场景：并发失败处理
- **当** 任一并发上传失败时
- **则** 系统应等待所有进行中的上传完成，然后清理所有已上传文件并返回错误
系统应优雅地处理 CDN 上传失败。

#### 场景：上传期间的网络错误
- **当** CDN 上传因网络错误失败时
- **则** 系统应重试最多 3 次，使用指数退避

#### 场景：认证错误
- **当** CDN 上传因认证错误失败时
- **则** 系统应返回 500 Internal Server Error 并附带错误"storage authentication failed"

#### 场景：配额超出
- **当** CDN 上传因配额限制失败时
- **则** 系统应返回 507 Insufficient Storage 并附带错误"storage quota exceeded"

### 需求：下载错误处理
系统应优雅地处理 CDN 下载失败。

#### 场景：CDN 中文件未找到
- **当** 尝试下载 CDN 中不存在的文件时
- **则** 系统应返回 404 Not Found

#### 场景：下载期间的网络错误
- **当** CDN 下载因网络错误失败时
- **则** 系统应重试最多 3 次，使用指数退避

### 需求：删除操作安全性
系统应实现带验证的安全删除。

#### 场景：带确认的删除
- **当** 从 CDN 删除文件时
- **则** 系统应在尝试删除之前验证文件是否存在

#### 场景：删除失败处理
- **当** CDN 删除操作失败时
- **则** 系统应记录错误但不使整个操作失败（孤立文件可接受）

### 需求：内容类型保存
系统应保存和验证存储文件的内容类型。

#### 场景：存储内容类型元数据
- **当** 上传文件到 CDN 时
- **则** 系统应根据文件扩展名设置适当的 Content-Type 响应头

#### 场景：使用正确的内容类型检索
- **当** 生成下载 URL 时
- **则** 系统应确保 URL 以正确的 Content-Type 响应头服务文件

### 需求：CDN 提供商配置
系统应支持配置不同的 CDN 提供商。

#### 场景：阿里云 OSS 配置
- **当** 配置 CDN 时
- **则** 系统应支持阿里云 OSS（S3 协议兼容）
- **配置项**：
  - endpoint: 阿里云 OSS 端点（如 oss-cn-hangzhou.aliyuncs.com）
  - bucket: 存储桶名称
  - accessKeyId: 访问密钥 ID
  - accessKeySecret: 访问密钥密码

#### 场景：S3 协议兼容
- **当** 配置 CDN 时
- **则** 系统应使用 S3 兼容协议与阿里云 OSS 通信

### 需求：后端中转上传
系统应通过后端中转上传文件到 CDN。

#### 场景：上传流程
- **当** 发布 skill 时
- **则** 文件上传流程为：
  1. 客户端发送 multipart form 到后端
  2. 后端验证文件和 payload
  3. 后端上传文件到阿里云 OSS
  4. 后端返回成功响应

#### 场景：不需要预签名 URL
- **当** 上传文件时
- **则** 系统不生成预签名 URL（所有上传通过后端）

### 需求：文件元数据管理
系统应管理和验证文件元数据。

#### 场景：文件列表存储
- **当** 创建新版本时
- **则** 系统应在 skill_versions.files JSONB 中存储所有文件的元数据

#### 场景：文件内容类型推断
- **当** 上传文件时
- **则** 系统应根据文件扩展名推断 Content-Type（如果未提供）

### 需求：CDN 性能优化
系统应实现性能优化以减少延迟和成本。

#### 场景：批量上传
- **当** 发布包含多个文件时
- **则** 系统应并行上传文件以提高速度

#### 场景：CDN 缓存策略
- **当** 生成公开 URL 时
- **则** 系统应配置适当的缓存控制头（Cache-Control: public, max-age=31536000）
