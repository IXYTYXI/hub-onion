## 新增需求

### 需求：通过内容哈希解析版本
系统应基于内容哈希匹配来解析 skill 版本。

#### 场景：哈希匹配解析
- **当** 客户端请求 GET /api/v1/resolve?slug={slug}&hash={hash} 时
- **则** 系统应返回与提供的哈希匹配的版本

#### 场景：没有匹配的哈希
- **当** 客户端请求的哈希与任何版本都不匹配时
- **则** 系统应返回 404 Not Found

#### 场景：多种哈希格式
- **当** 客户端以不同格式提供哈希时（有或没有算法前缀）
- **则** 系统应规范化并正确比较哈希

### 需求：从文件列表计算哈希
系统应从所有文件的组合 SHA-256 哈希计算版本哈希。

#### 场景：确定性哈希计算
- **当** 计算版本哈希时
- **则** 系统应按排序顺序连接文件哈希并计算结果的 SHA-256

#### 场景：哈希与版本一起存储
- **当** 创建新的 skill 版本时
- **则** 系统应计算版本哈希并将其存储到 skill_versions 表中

### 需求：最新版本比较
系统应将请求的哈希与最新版本进行比较以确定是否需要更新。

#### 场景：哈希与最新版本匹配
- **当** 解析请求的哈希与最新版本哈希匹配时
- **则** 系统应返回响应表明不需要更新

#### 场景：哈希与最新版本不同
- **当** 解析请求的哈希与最新版本哈希不同时
- **则** 系统应返回最新版本信息以进行更新

### 需求：解析响应格式
系统应以标准化格式返回版本解析信息。

#### 场景：有可用更新的响应
- **当** 存在更新版本时
- **则** 系统应返回 JSON，包含 updateAvailable: true、latestVersion 和 downloadUrl

#### 场景：最新状态响应
- **当** 客户端拥有最新版本时
- **则** 系统应返回 JSON，包含 updateAvailable: false 和 currentVersion

### 需求：技能存在性验证
系统应在尝试版本解析之前验证技能是否存在。

#### 场景：技能未找到
- **当** 客户端请求不存在的 slug 的解析时
- **则** 系统应返回 404 Not Found 并附带错误消息"skill not found"

#### 场景：已删除的技能
- **当** 客户端请求已删除技能的解析时
- **则** 系统应返回 404 Not Found

### 需求：解析请求格式
系统应正确解析版本解析请求参数。

#### 场景：slug 参数
- **当** 客户端请求解析时
- **则** 请求应包含 slug 参数

#### 场景：hash 参数
- **当** 客户端请求解析时
- **则** 请求应包含 hash 参数（可选，用于比较）

#### 场景：version 参数
- **当** 客户端请求解析时
- **则** 请求可包含 version 参数（可选，用于指定版本）

### 需求：解析响应格式
系统应按照标准 schema 格式返回版本解析结果。

#### 场景：标准解析响应结构
- **当** 解析请求成功时
- **则** 系统应返回 JSON 响应，包含：
  - match: object | null（匹配的版本，包含 version 字段）
  - latestVersion: object | null（最新版本，包含 version 字段）

#### 场景：哈希匹配响应
- **当** 提供的哈希与某个版本匹配时
- **则** 系统应返回 `{ "match": { "version": "1.0.0" }, "latestVersion": { "version": "1.0.0" } }`

#### 场景：无匹配响应
- **当** 没有版本与提供的哈希匹配时
- **则** 系统应返回 `{ "match": null, "latestVersion": { "version": "1.1.0" } }`

### 需求：解析错误处理
系统应正确处理解析相关的错误情况。

#### 场景：技能未找到
- **当** 请求的 slug 不存在时
- **则** 系统应返回 404 并附带 `{ "error": "skill not found" }`

#### 场景：参数缺失
- **当** 请求缺少必要的 slug 参数时
- **则** 系统应返回 400 并附带 `{ "error": "missing slug parameter" }`
