## Context

当前首页已经通过 [`src/components/InstallSwitcher.tsx`](/Users/logo/self_repo/claw_case/clawhub/src/components/InstallSwitcher.tsx) 提供快捷安装命令和复制能力，并通过 [`src/lib/install-command.ts`](/Users/logo/self_repo/claw_case/clawhub/src/lib/install-command.ts) 统一处理 npm registry、CLI 包名和 skill registry 的环境变量读取与回退逻辑。

技能详情页头部操作区位于 [`src/components/SkillHeader.tsx`](/Users/logo/self_repo/claw_case/clawhub/src/components/SkillHeader.tsx)。当前这里只展示版本信息和“下载 ZIP”按钮，没有针对当前 skill 的安装命令，也没有复制能力。

本需求的关键约束已经明确：

- 首页现有快捷安装区域不改
- 详情页命令拼接必须复用当前 env 规则，不能写死地址

## Goals / Non-Goals

**Goals:**
- 在技能详情页下载按钮下方补齐快捷安装命令展示
- 让详情页命令基于当前 skill slug 动态生成
- 复用现有命令拼接规则，保证多环境独立性
- 复用现有复制交互模式，降低行为分叉风险

**Non-Goals:**
- 不重构首页 Hero 快捷安装区域
- 不新增 pnpm、bun 等安装器切换能力
- 不修改后端接口或下载 ZIP 行为
- 不引入新的环境变量命名方案

## Decisions

### 决策 1：详情页新增能力，不改首页

原因：

- 首页现有能力已经可用
- 用户确认首页不需要修改
- 将需求局限在详情页可以避免无关回归

备选方案：

- 同时重做首页与详情页的快捷安装区域

不采用原因：

- 需求边界不需要
- 会扩大视觉与交互回归面

### 决策 2：命令生成继续复用 `src/lib/install-command.ts`

详情页命令必须继续通过现有工具函数生成，而不是在详情页单独拼接字符串。

原因：

- 当前 env 与回退策略已经集中在一个文件
- 不同环境依赖这一套规则维持独立配置
- 命令生成逻辑若分散，会导致首页与详情页后续漂移

备选方案：

- 在详情页本地直接读取 env 并重新拼接命令

不采用原因：

- 重复实现
- 容易出现回退逻辑不一致

### 决策 3：优先复用现有复制交互能力，而不是重新写一套

详情页复制能力应尽量复用首页已有的复制状态机与成功态模式。实现上可以：

- 扩展 `InstallSwitcher` 使其支持详情页文案与当前 slug
- 或抽取更底层的共享命令条组件，由首页和详情页共同使用

本次设计不强制具体代码组织，但要求满足两个结果：

- 复制交互一致
- 命令生成逻辑不重复

备选方案：

- 在详情页新写一套复制按钮与定时回退逻辑

不采用原因：

- 容易与首页行为分叉
- 增加重复维护成本

### 决策 4：详情页仅展示 npm 命令

当前首页实际只开放 `npm` 这一项，详情页也应保持一致。

原因：

- 与现状一致
- 本次需求核心是补齐详情页能力，不是扩展安装器矩阵

备选方案：

- 在详情页同时开放 pnpm、bun 等切换项

不采用原因：

- 当前项目并未对这些切换项形成稳定产品能力
- 会扩大需求范围

## Risks / Trade-offs

- [复制逻辑复用不彻底] → 若详情页单独实现复制状态，短期可用但长期可能与首页出现文案、时序或异常处理差异；优先抽共享能力降低分叉
- [样式复用过重] → 若直接把首页 Hero 结构搬到详情页，可能破坏详情页头部层级；应只复用命令条和交互，不复用整块布局
- [长命令在窄屏溢出] → 需要确保命令展示区域支持换行或滚动，并保持复制按钮可点击
- [环境变量规则被绕过] → 若后续有人在详情页改为手写命令模板，会破坏多环境独立性；应让详情页直接依赖统一工具函数

## Migration Plan

1. 在详情页操作区引入快捷安装展示区域
2. 将命令生成绑定到当前 skill slug，并继续复用现有安装命令工具函数
3. 复用或抽取复制能力，使首页与详情页保持一致行为
4. 验证首页不受影响，详情页在不同 env 下能正确展示命令

该需求为纯前端增强，无数据库或后端迁移步骤。

回滚策略：

- 若出现问题，可仅移除详情页新增快捷安装区域
- 首页现有快捷安装区域不受本次变更影响
