## Why

ClawHub 已确认采用“飞书主登录、邮箱辅助登录”的最终账号方案，但当前系统的认证与账号语义仍围绕邮箱注册/登录和 GitHub/GitLab OAuth 设计。为了支持飞书客户端内免登、保持本地用户主体不分裂，并将管理权限继续约束在“已绑定邮箱”的本地用户上，需要为现有身份体系补充飞书授权、邮箱绑定和统一账号规则。

## What Changes

- 新增飞书主登录能力，支持在飞书客户端内通过 `requestAccess` 免登进入平台，并在普通浏览器中通过标准 OAuth 重定向进入平台。
- 明确飞书工作台唤起浏览器进入平台属于独立增强场景，不与普通浏览器飞书登录混淆，本期不作为必须能力。
- 新增飞书身份绑定能力，使历史邮箱用户可以将飞书身份绑定到已有本地用户。
- 新增邮箱绑定能力，使飞书主登录用户可以补充并验证邮箱身份。
- 重新定义邮箱注册 / 激活 / 登录链路的职责：
  - 邮箱注册用于发起邮箱绑定
  - 邮箱激活用于验证邮箱并完成绑定
  - 邮箱登录作为辅助方式进入已有本地用户
- 明确统一账号模型：飞书身份和邮箱身份都是本地用户的绑定身份，平台唯一账号主体始终是本地用户 `users.id`。
- 明确管理权限规则：未绑定邮箱的飞书用户只能是普通用户；管理员和超级管理员必须依附已绑定邮箱的本地用户。
- 调整前端登录页与设置页语义，使其体现“飞书为主、邮箱兼容保留”的登录与绑定策略，并区分浏览器 OAuth 导航链路与 API 代理链路。
- 调整设置页与用户消息展示规则，飞书原始标识仅用于后端存储和匹配，不直接暴露给用户。

## Capabilities

### New Capabilities
- `feishu-auth`: 定义飞书主登录、飞书绑定、邮箱绑定与统一账号模型下的登录入口行为。

### Modified Capabilities
- `user-identity`: 扩展本地用户与外部身份映射规则，明确飞书身份、邮箱身份与本地用户主体的收敛关系。
- `user-review-workflow`: 调整审核与管理权限规则，确保未绑定邮箱的飞书用户不能获得管理权限，并允许已绑定邮箱的本地用户继续参与现有审核/管理体系。

## Impact

- Affected docs:
  - `docs/feishu_auth/requirements.md`
  - `docs/feishu_auth/technical-design.md`
- Affected backend areas:
  - `/auth/*` 认证路由
  - 用户身份映射与邮箱绑定逻辑
  - 本地 session 颁发逻辑
  - 管理权限前置校验
- Affected frontend areas:
  - 登录页
  - 设置页账号绑定区块
  - 运行环境检测、飞书内登录入口与浏览器飞书登录入口
- Affected data model:
  - `users` 的邮箱绑定状态语义
  - `auth_identities` 的飞书身份存储与绑定规则
