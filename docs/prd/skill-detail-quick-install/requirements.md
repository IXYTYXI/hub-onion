# 技能详情页快捷安装命令需求文档

## 1. 文档目的

本文档用于定义“在技能详情页下载按钮下方增加快捷安装命令与复制能力”的需求边界，作为后续设计、开发与验收依据。

本需求以当前仓库代码现状为基础编写，强调与首页现有快捷安装能力保持一致的用户体验，同时保持不同环境之间的配置独立性。

## 2. 背景

当前首页已经存在快捷安装命令展示与复制能力：

- 首页 `Hero` 区域中已提供安装命令展示
- 命令内容通过现有 env 变量拼接生成
- 用户可以直接复制命令到终端执行

但技能详情页当前只有“下载 ZIP”按钮，没有提供：

- 针对当前 skill 的快捷安装命令
- 与首页一致的复制能力

这会导致两个问题：

- 用户在详情页已经明确决定安装某个 skill，却仍需要自行组织命令
- 首页和详情页在“安装”主路径上的体验不一致

## 3. 核心目标

本次需求的核心目标如下：

1. 在技能详情页下载按钮下方新增“快捷安装”展示区域
2. 向用户展示针对当前 skill slug 的完整 CLI 安装命令
3. 提供与首页一致的复制能力和复制成功反馈
4. 命令拼接必须复用当前项目已有的 env 变量规则
5. 保持首页现有快捷安装区域不变，不对首页做视觉或交互修改

## 4. 范围

### 4.1 本次必须覆盖

- 技能详情页下载按钮下方新增快捷安装区域
- 快捷安装区域展示当前 skill 对应的 CLI 安装命令
- 快捷安装区域提供复制按钮
- 复制成功后提供明确反馈
- 命令拼接规则复用当前已有实现中的 env 变量来源与回退逻辑
- 移动端和桌面端都能正常展示该区域

### 4.2 本次建议覆盖

- 详情页快捷安装区域在视觉上尽量与首页现有快捷安装条保持一致
- 命令区域支持长命令换行或横向滚动，避免遮挡复制按钮
- 为后续抽取共享组件保留空间

### 4.3 本次明确不做

- 不修改首页现有快捷安装区域文案、布局或交互
- 不新增新的 env 变量命名方案
- 不新增 pnpm、bun 等新的安装器切换项
- 不修改下载 ZIP 按钮本身的行为
- 不改动后端接口

## 5. 问题定义

### 5.1 详情页缺少安装主路径

技能详情页是用户决定安装某个 skill 的关键页面，但当前这里只有下载 ZIP 的入口，没有“直接安装”命令展示。

### 5.2 复制能力没有在详情页复用

首页已有复制安装命令的能力，但详情页没有同样的交互，导致用户需要手动选中、复制或自己补全命令。

### 5.3 环境独立性必须被保留

当前首页安装命令并不是写死地址，而是通过 env 变量拼接：

- CLI npm registry
- CLI package name
- skill registry 地址

这一机制保证了不同环境下命令可自动适配。

因此详情页不能手写命令模板或写死 registry 地址，必须复用现有规则，否则会破坏测试、预发、生产等环境之间的独立性。

## 6. 产品方案

### 6.1 页面位置

新增区域位于技能详情页中：

- 当前版本信息区域下方
- “下载 ZIP”按钮下方

该区域与下载按钮属于同一操作组，但语义上区分为：

- 下载 ZIP：获取压缩包
- 快捷安装：直接通过 CLI 安装当前 skill

### 6.2 展示内容

快捷安装区域包含：

- 区块标题，例如“快捷安装”
- 简短说明，例如“复制命令后可直接在终端安装当前技能”
- 命令展示框
- 复制按钮
- 复制成功反馈

默认只展示 `npm` 对应的命令形式，不引入新的切换项。

### 6.3 命令内容

命令必须面向当前详情页 skill 动态生成，命令中需包含：

- 当前 skill 的 `slug`
- 当前环境对应的 npm registry
- 当前环境对应的 CLI 包名
- 当前环境对应的 skill registry 地址

示例形态如下：

```bash
npx --registry <npm-registry> <cli-package> install <skill-slug> --registry <skill-registry>
```

### 6.4 首页策略

首页现有快捷安装区域保持原状：

- 不改文案
- 不改布局
- 不改交互

本次需求只在技能详情页补齐同类能力，不对首页做收口或重构。

## 7. 一致性要求

### 7.1 命令拼接一致性

技能详情页的命令生成规则必须与首页当前规则一致。

具体要求：

- 复用现有 env 变量读取逻辑
- 复用现有回退逻辑
- 不能在详情页单独维护一套写死字符串

### 7.2 交互一致性

详情页复制体验应与首页保持一致，包括：

- 复制按钮位置与用途清晰
- 成功态文案一致或接近
- 失败时不产生误导性成功提示

## 8. 验收标准

### 8.1 页面展示

- 打开任意技能详情页时，可以在下载按钮下方看到快捷安装区域
- 区域中展示的命令包含当前技能 slug
- 命令内容不是写死示例 slug

### 8.2 复制行为

- 点击复制按钮后，可以复制当前展示命令
- 复制成功后出现成功反馈
- 再次进入其他 skill 详情页时，复制内容会切换为该 skill 对应命令

### 8.3 环境配置

- 在不同环境下，命令中的 registry / package 信息可根据 env 自动变化
- 详情页命令与首页命令在同一环境下的拼接规则一致
- 不允许出现首页与详情页使用不同 registry 来源的情况

### 8.4 非目标确认

- 首页视觉与交互保持不变
- 下载 ZIP 入口保持不变
- 后端 API 无需改动

## 9. 风险与约束

- 浏览器剪贴板能力在部分非安全上下文下可能受限，需要沿用当前已有处理方式
- 若详情页自行维护命令模板，后续极易出现与首页规则漂移的问题，因此必须避免重复实现
- 命令较长时需要考虑窄屏展示，否则会影响复制按钮可用性

## 10. 结论

本需求本质上是把首页已有的快捷安装能力，按详情页场景补齐到技能详情页中，但不是简单复制 UI。

真正关键点有两个：

1. 详情页必须能基于当前 skill 生成正确命令
2. 命令生成必须继续服从现有 env 变量拼接规则，保证各环境独立性
